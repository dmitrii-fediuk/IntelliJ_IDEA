# «Dmitrii Fediuk» Plugin (`df.idea`)

A unified local `IntelliJ IDEA` plugin that groups custom IDE extensions into independent feature packages and modular documentation sections.  
The plugin lives self-contained inside its repository root and is loaded directly via the `plugin.path` property in `idea.properties` of active IDE installations (`IntelliJIdea2026.2`, `IntelliJIdea2026.3`) without copying the JAR into the IDE `plugins/` directory.

## 1. Repository Layout

1. `⛯` — source code, plugin descriptor, automated tests, and the build script ([build.ps1](../⛯/build.ps1)).  
1. `🕮` — plugin and feature documentation ([features/copy-reference.md](features/copy-reference.md), [features/markdown-code-fence.md](features/markdown-code-fence.md), [features/path-macros.md](features/path-macros.md), [features/project-roots.md](features/project-roots.md), [features/update-source.md](features/update-source.md)).  
1. `≻` — build outputs: deterministic executable artifact [df-idea.jar](../≻/df-idea.jar) and synchronized local repository descriptor [updatePlugins.xml](../≻/updatePlugins.xml).

## 2. Architecture and Feature Modules

Each feature is isolated in its own package under `df.idea.feature.<name>` with zero cross-feature dependencies:

1. `df.idea.feature.copyreference` — honors outer-module `<excludeFolder>` boundaries during `CopyReference` (`Ctrl+Q`); see [features/copy-reference.md](features/copy-reference.md).  
1. `df.idea.feature.markdowncodefence` — suppresses the hardcoded `MARKDOWN_CODE_FENCE_BACKGROUND` full-width custom background renderer added in `IntelliJ IDEA 2026.3`, restoring plain fenced code blocks without affecting injected language fragments; see [features/markdown-code-fence.md](features/markdown-code-fence.md).  
1. `df.idea.feature.pathmacros` — loads project-scoped path variables from UTF-8 `.properties` files inside ancestor `.idea` directories (`$df.m$` and any additional custom variables); see [features/path-macros.md](features/path-macros.md).  
1. `df.idea.feature.projectroots` — removes redundant nested `ProjectRootEntity` instances strictly inside any module content root, restoring module ownership and visibility of nested project directories in `Project Files`; see [features/project-roots.md](features/project-roots.md).  
1. `df.idea.feature.updatesource` — advertises the local [updatePlugins.xml](../≻/updatePlugins.xml) repository via `UpdateSettingsProvider` and automatically registers the update source in the currently running IDE instance without editing `pluginUpdateSources.xml` directly; see [features/update-source.md](features/update-source.md).

Shared entry points and test harness:

1. [plugin.xml](../⛯/src/main/resources/META-INF/plugin.xml) — unified plugin descriptor (`<id>df.idea</id>`, `<name>Dmitrii Fediuk</name>`, `<vendor url="https://github.com/dmitrii-fediuk">Dmitrii Fediuk</vendor>`, `<idea-version since-build="262"/>` without `until-build`, `<depends>com.intellij.modules.lang</depends>`).  
1. [Assertions.java](../⛯/src/test/java/df/idea/support/Assertions.java) — minimal assertion helper shared by unit and integration tests.  
1. [PluginDescriptorVerificationTest.java](../⛯/src/test/java/df/idea/plugin/PluginDescriptorVerificationTest.java) — end-to-end verification of the built JAR and `idea.properties` loading against actual `IntelliJ IDEA` runtime classes (`PathManager`, `PluginDescriptorLoader`, `PluginManagerCore`, `PluginCompatibilityUtils`).

### Adding a New Feature

1. Create a dedicated package under `⛯/src/main/java/df/idea/feature/<feature>/` separating pure domain logic from a thin adapter to `IntelliJ Platform` APIs.  
1. Add isolated tests under `⛯/src/test/java/df/idea/feature/<feature>/` and register the test class in `$featureTests` inside [build.ps1](../⛯/build.ps1).  
1. Register extensions or listeners in [plugin.xml](../⛯/src/main/resources/META-INF/plugin.xml) and verify them in [PluginDescriptorVerificationTest.java](../⛯/src/test/java/df/idea/plugin/PluginDescriptorVerificationTest.java).  
1. Document the feature in `🕮/features/<feature>.md` and add a link in section 2 of this file.

## 3. IDE Integration and Upgrade Resilience

In `idea.properties` of installed IDE instances (e.g., `%APPDATA%/JetBrains/IntelliJIdea2026.3/idea.properties` and `%APPDATA%/JetBrains/IntelliJIdea2026.2/idea.properties`), configure `plugin.path` to point directly to [df-idea.jar](../≻/df-idea.jar):

```properties
plugin.path=<plugin-root>/≻/df-idea.jar
```

1. At startup, the IDE invokes `PathManager.loadProperties()` (reading `idea.properties` as UTF-8, including non-BMP Unicode characters such as `𝐏`), and `PluginDescriptorLoader.loadDescriptorsFromProperty` loads the JAR directly from `≻/` under `PluginsSourceContext.SystemPropertyProvided`.  
1. Because [plugin.xml](../⛯/src/main/resources/META-INF/plugin.xml) omits `until-build`, `PluginManagerCore.isIncompatible` accepts every build starting from `262` (`262.*`, `263.*`, `271.*`, and newer).  
1. `idea.properties` persists across minor updates and is migrated via `ConfigImportHelper.doImport` during major IDE upgrades.  
1. In `IntelliJ IDEA 2026.3+`, the plugin registers its sibling [updatePlugins.xml](../≻/updatePlugins.xml) through the active IDE instance's `PluginUpdateSourceService` (`isMarketplace="false"`), preserving `IJPL-171317` protection against Marketplace substitution for `df.idea`.

## 4. Building, Testing, and Installing

The script [build.ps1](../⛯/build.ps1) compiles the project with the bundled `JBR` from `IntelliJ IDEA` (zero Gradle, Maven, or external build dependencies), enforces `-Xlint:all -Werror`, builds byte-reproducible [df-idea.jar](../≻/df-idea.jar) and [updatePlugins.xml](../≻/updatePlugins.xml), and runs all unit and integration suites before writing outputs:

```powershell
# Build and run all tests without modifying idea.properties (close IntelliJ IDEA first)
powershell -NoProfile -ExecutionPolicy Bypass -File "<plugin-root>\⛯\build.ps1"

# Compile and run all tests in a temporary directory only (safe while IDE is running)
powershell -NoProfile -ExecutionPolicy Bypass -File "<plugin-root>\⛯\build.ps1" -VerifyOnly

# Build, test, register plugin.path in idea.properties of the target IDE, and run loader verification
powershell -NoProfile -ExecutionPolicy Bypass -File "<plugin-root>\⛯\build.ps1" -Install
```

With `-Install`, the script idempotently writes `df-idea.jar` into `plugin.path` of the target IDE instance (`-IdeaHome` or the newest installed IDE), removes any superseded `df-copy-reference.jar` entry from `plugin.path`, and ensures no duplicate JAR exists in that instance's `plugins/` directory; `pluginUpdateSources.xml` is never edited by the build script.  
In the `IntelliJ IDEA` UI (`Settings | Plugins | Installed`), the plugin appears as `Dmitrii Fediuk`.
